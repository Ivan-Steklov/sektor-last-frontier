# Progress — Сектор: Последний Рубеж

## Текущий статус
Проект развивается как компактная асинхронная космическая стратегия для Telegram Mini App.
Подход: маленькие vertical slice, backend-first, frontend только отображает состояние и отправляет команды.

Сейчас рабочий контур уже включает:
- одну планету;
- ресурсы;
- здания;
- исследования;
- корабли;
- экспедиции;
- сектор галактики;
- разведывательные миссии по системам;
- сохранение известных систем;
- ресурсные миссии по разведанным системам;
- риск-исходы ресурсных миссий.

---

## Архитектурные правила
- Backend — источник истины.
- Backend отвечает за:
  - синхронизацию и списание ресурсов;
  - очереди и завершение миссий;
  - доступность, возврат и потерю кораблей;
  - результаты разведки;
  - результаты ресурсных миссий и риск.
- Frontend:
  - показывает состояние;
  - отправляет команды на backend;
  - крутит локальные countdown-таймеры;
  - не рассчитывает игровую логику.

## Галактика

### Сектор
Добавлен детерминированный сектор галактики:
- маршрут:
  - `GET /api/galaxy/sector?telegram_id=1`
- сектор стабильно отображается на frontend.

### Разведка систем
Добавлены разведывательные миссии:
- маршруты:
  - `GET /api/galaxy/scout/current?telegram_id=1`
  - `POST /api/galaxy/scout/start?telegram_id=1`

Поведение:
- нужна `1 scout`;
- при старте разведки корабль временно убирается из доступного флота;
- после завершения возвращается;
- одновременно может быть только одна активная разведка;
- отчет по системе сохраняется в БД.

### Известные системы
Добавлено постоянное хранение разведанных систем:
- таблица:
  - `galaxy_known_systems`
- уникальность:
  - `(planet_id, target_galaxy, target_system)`
- индекс/constraint:
  - `uq_galaxy_known_system_planet_target`

Поведение:
- повторная разведка не создает дубликат;
- вместо этого обновляет сохраненный отчет.

### UI галактики
Во frontend добавлено:
- выделение уже разведанных систем;
- отображение отчета по системе;
- кнопка повторной разведки;
- скрытие richness/danger для неразведанных систем;
- корректный прогресс по сектору без домашней системы в знаменателе.

## Ресурсные миссии в галактике

### Основной цикл
Добавлены ресурсные миссии:
- маршруты:
  - `GET /api/galaxy/resource-mission/current?telegram_id=1`
  - `POST /api/galaxy/resource-mission/start?telegram_id=1`

Условия:
- система должна быть разведана;
- нужна `1 transport`;
- одновременно только одна активная ресурсная миссия на планету.

Поведение:
- transport убирается из доступного флота на время миссии;
- после завершения миссия приносит `metal` и `crystal`;
- возврат транспорта зависит от исхода миссии.

### Хранение миссий
Добавлена таблица:
- `galaxy_resource_missions`

Индекс:
- `ix_galaxy_resource_mission_one_active_per_planet`

---

## Риск в ресурсных миссиях
Риск считается на backend на основе danger из разведотчета.

### Правила риска
- low danger:
  - полная награда;
  - transport возвращается.
- medium danger:
  - потеря 30% груза.
- high danger:
  - либо полная потеря transport;
  - либо потеря 50% груза.

### Расширение ответа миссии
В результат миссии добавлены поля:
- `danger`
- `danger_level`
- `transport_lost`
- `cargo_loss_percent`

## Совместимость со старыми данными
После добавления новых risk-полей старые записи в `result_payload` вызывали ошибку валидации Pydantic:

- `pydantic_core._pydantic_core.ValidationError`
- отсутствовали:
  - `danger`
  - `danger_level`

Исправление:
- в `backend/app/galaxy/service.py` добавлена нормализация старых payload:
  - `_normalize_resource_result_payload(payload: dict) -> dict`
- `get_galaxy_resource_mission_state()` теперь читает старые записи безопасно.

Это устраняет backend 500 на:
- `GET /api/galaxy/resource-mission/current?telegram_id=1`

Без обязательной миграции уже сохраненных JSON.

### Исправление округления
Раньше в тестах была проблема с округлением:
- ожидалось `252`, приходило `251`

Причина:
- использовалось float-округление через `int(...)`

Исправление:
- переход на целочисленную математику:
  - `metal_found * 70 // 100`
  - `crystal_found * 70 // 100`
  - и аналогично для 50%

Возможные варианты следующего slice:

### Улучшение UX риска в галактике
Во frontend улучшена читаемость risk-механики:
- разведанные системы на карте получили явные risk badges;
- danger level подсвечивается цветом;
- в карточке разведанной системы показывается краткий прогноз resource mission;
- результат resource mission визуально выделяется по типу исхода.
### Выравнивание frontend с реальным galaxy API
Frontend экрана галактики приведен к фактической схеме backend response:
- активные mission state используют `finishes_at` и `remaining_seconds`;
- `danger_level` обрабатывается как integer, а не строковый enum;
- sector screen использует `scout_report`, `is_scouted`, `has_home_planet`, `current_galaxy`.

Countdown scout/resource missions теперь строится от `remaining_seconds`, вычисленного backend, а frontend только локально отображает уменьшение таймера.
### UI: расширенная карточка разведанной системы
В galaxy UI улучшено отображение разведанных систем:
- в карточке системы теперь показывается отдельный блок `Отчет разведки`;
- отображается `description` из scout report;
- показываются найденные сигналы (`discovered_signals`);
- показывается время последней разведки (`completed_at`) в человекочитаемом формате.

Изменение не затрагивает backend-контракт: используются уже существующие поля `scout_report`.
### UI: отдельный блок "Последний отчет разведки"
В galaxy UI добавлен нижний агрегированный блок `Последний отчет разведки`, аналогичный блоку последней ресурсной миссии.

Что показывает блок:
- систему отчета;
- richness;
- danger / risk;
- количество найденных сигналов;
- дату завершения разведки;
- текстовое описание отчета.

Дополнительно:
- если игрок выбрал другую систему, UI явно поясняет, что последний разведотчет относится не к текущему выбору.
### UI: подсветка целей активных миссий в галактике
В galaxy UI добавлена визуальная подсветка систем, в которые сейчас направлены активные миссии:
- метка `Разведка` для активной scout mission;
- метка `Транспорт` для активной resource mission;
- если выбрана целевая система, в карточке показывается локальный статус-блок с обратным отсчетом.

Изменение полностью frontend-only и использует уже существующие поля:
- `scoutState.active_mission`
- `resourceMissionState.active_mission`
### Backend: выровнены galaxy schemas под текущие router/service импорты
После попытки перевода galaxy schemas на новые имена классов был найден рассинхрон:
- `router.py` и `service.py` продолжали импортировать старые имена схем;
- это делало `schemas.py` несовместимым с остальным galaxy backend.

Исправление:
- в `backend/app/galaxy/schemas.py` возвращены текущие используемые имена схем:
  - `GalaxySectorResponse`
  - `GalaxyScoutStateResponse`
  - `GalaxyResourceMissionStateResponse`
  - и связанные response/request модели;
- при этом сохранена явная ISO-сериализация datetime через `field_serializer`.

Результат:
- backend-импорты снова консистентны;
- galaxy API отдает стабильные datetime-строки без переписывания service/router.
